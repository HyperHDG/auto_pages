Detailed Description

The .geo.h5 domain file format and the HDF5 calls to read and write it.

A .geo.h5 file holds the same information as a .geo file (cf. read_domain_geo) in the group /domain, as plain two-dimensional datasets that NumPy/h5py read directly: 

/domain/points        (n_points,     space_dim)      float   coordinates
/domain/edges         (n_hyEdges,    2^hyEdge_dim)   int     point indices per hyperedge
/domain/hypernodes    (n_hyEdges,    2 hyEdge_dim)   int     hypernode indices per hyperedge
/domain/types_faces   (n_hyEdges,    2 hyEdge_dim)   int     face types (boundary conditions)
/domain/types_points  (n_points,     1)              int     derived (hyEdge_dim 1): max
                                                             type of the faces at a point
/domain/properties    (n_hyEdges,    n_properties)   float   optional per-hyperedge data

with the attributes space_dim, hyperedge_dim and n_hypernodes on /domain (integers; further attributes are ignored). hypernodes is optional: without it, hypernodes are numbered like points (one hypernode per point), which is the case for networks (hyEdge_dim 1) and the convention of the Python network generators. Files written by write_domain_hdf5 for hyEdge_dim 1 contain no hypernodes dataset if the numbering agrees.

python/geo2h5.py converts a .geo file into this format. The group /VTKHDF (optional, written by default) is a VTKHDF unstructured grid view of the same data for ParaView: Points and the point/cell data are links into /domain, and the Connectivity of a network is a virtual dataset over /domain/edges, so the view costs nothing but a few small arrays. ParaView chooses its reader by file extension, so open a .geo.h5 file with File > Open and pick "VTKHDF Reader" when asked.

Reading is one H5Dread per dataset into the (contiguous) containers of DomainInfo; types are converted by HDF5, so int32 files load into unsigned int indices and float32 points into double. The layout is row-major per hyperedge, which is what a later per-rank hyperslab read needs.

Requires HyperHDG to be configured with HDF5 (CMake option HYPERHDG_HDF5, which defines HYPERHDG_HAVE_HDF5). The functions throw std::runtime_error on malformed files.

Write the VTKHDF unstructured-grid view of /domain into file.

Hyperedges become VTK lines, quads or hexahedra (hyEdge_dim 1, 2, 3). Points are linked for three space dimensions and zero-padded otherwise (VTK wants three coordinates). For networks the connectivity is a virtual dataset over /domain/edges; for quads and hexahedra the lexicographic vertex order of a hypercube is permuted into VTK's order.
