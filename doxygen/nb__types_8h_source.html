165// *WARNING*: nanobind regularly receives requests from users who run it
166// through Clang-Tidy, or who compile with increased warnings levels, like
167//
168// -Wcast-qual, -Wsign-conversion, etc.
169//
170// (i.e., beyond -Wall -Wextra and /W4 that are currently already used)
171//
172// Their next step is to open a big pull request needed to silence all of
173// the resulting messages. This comment is strategically placed here
174// because the (PyObject *) casts below cast away the const qualifier and
175// will almost certainly be flagged in this process.
176//
177// My policy on this is as follows: I am always happy to fix issues in the
178// codebase. However, many of the resulting change requests are in the
179// "ritual purification" category: things that cause churn, decrease
180// readability, and which don't fix actual problems. It's a never-ending
181// cycle because each new revision of such tooling adds further warnings
182// and purification rites.
183//
184// So just to be clear: I do not wish to pepper this codebase with
185// "const_cast" and #pragmas/comments to avoid warnings in external
186// tooling just so those users can have a "silent" build. I don't think it
187// is reasonable for them to impose their own style on this project.
188//
189// As a workaround it is likely possible to restrict the scope of style
190// checks to particular C++ namespaces or source code locations.
